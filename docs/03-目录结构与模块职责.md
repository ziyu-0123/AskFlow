## 3. 模块职责速查表

| 模块                              | 职责                                                     | 不负责                        |
| ------------------------------- | ------------------------------------------------------ | -------------------------- |
| `router`                        | 路由表、懒加载、路径常量、`isLoginOrRegister`/`isNoNeedUserInfo` 判断 | 鉴权执行（由 layouts 内 hooks 完成） |
| `layouts`                       | 页面壳、鉴权重定向、导航入口                                         | 业务逻辑                       |
| `pages`                         | 页面编排、本地 UI 状态、请求触发                                     | 全局状态定义                     |
| `components/QuestionComponents` | 问卷组件的渲染/属性编辑/统计三视图协议                                   | 组件数据的增删改（在 store）          |
| `components/DragSortable`       | dnd-kit 的 Container/Item 泛化封装                          | 排序后的状态更新（回调给调用方 dispatch）  |
| `store`                         | 编辑器状态的唯一真相源（含撤销历史）                                     | 发请求、持久化（保存由 EditHeader 触发） |
| `hooks`                         | 数据加载→store 同步、store 读取、快捷键                             | 直接渲染 UI                    |
| `services`                      | HTTP 细节、类型定义、数据归一                                      | 状态管理                       |
| `utils`                         | 无关业务的纯工具（token 存取）                                     | —                          |
| `constant`                      | 跨模块共享字面量                                               | —                          |

## 4. 命名约定

* 问卷组件配置目录统一 `Question{Xxx}`，内部四件套 `Component / PropComponent / StatComponent / interface`。

* 页面级样式用与页面同名的 `*.module.scss`（CSS Modules）；个别全局样式在 `index.css`。

* Redux action 采用"动词 + 名词"驼峰（如 `changeComponentProps`、`resetComponents`）。

* service 函数统一 `xxxService` 后缀；类型统一 `XxxType` 后缀。
