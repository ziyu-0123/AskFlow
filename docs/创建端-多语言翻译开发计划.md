## 一、开发前分析（结合项目当前情况）

### 1.1 架构演进：为什么选方案 D（同卷多语言视图）

曾考虑的三个方案对比：

| | A. 翻译副本（独立问卷文档） | B. 原地替换 | **D. 同卷多语言视图（已选）** |
|---|---|---|---|
| 分享独立链接 | ✅ 各自 URL | ✅ | ✅ `?lang=en` |
| **跨语言统一统计** | ❌ 按语言分裂 | ✅ | ✅ **天然合并** |
| 原卷保护 | ✅ 副本隔离 | ❌ 摧毁原卷 | ✅ 主版本不动，译文只存 texts |
| 改动面 | 后端 1 接口 + 前端 1 弹窗（零侵入） | 同 D | Question schema + C 端渲染 + 编辑器弹窗（3 个开发点） |
| 适用场景 | 面向不同群体分别调研 | 不可接受 | **同一群体混合语言**（如国际化班级统一统计） |

**选 D 的决定性理由**（用户场景）：统计一个班的学生情况，班上有不同国家学生——需要所有人（无论填哪种语言版本）的答卷汇入同一份统计。副本方案做不到；而现有统计链路聚合的是选项 `value`（item1..itemN），与文案无关，**只要各语言共享同一套 fe_id 和 value，答卷在数据层就是同一把尺子**，统计页零改动天然合并。

### 1.2 现有架构对该功能的支撑度：高

| 现有设施 | 复用方式 |
|---|---|
| `chatWithRetry`（AiService 泛型私有方法） | 翻译与生成/优化同构：调 LLM → 解析 → zod 校验 → 失败反馈重试 1 次，直接复用 |
| `componentSchema`（7 种组件 discriminatedUnion） | **翻译输出契约核心**：翻译前后 props 结构完全同构，同一份 schema 校验，保证译文不破坏组件结构 |
| `normalizeOptions`（options/list 重写 value=itemN） | 翻译**不使用**（输出只被抽取 text）；zod strip 未知字段的特性使入参投影（剥离 value/checked/fe_id 等结构字段）自动完成 |
| `requireAiConfig` / `createClient` / `mapLlmError` | 未配置检查、动态 client、错误映射全部复用 |
| `aiConfigured`（Redux）+ AISettingsModal | 未配置引导与"请先配置"Redux 过期兜底照搬功能点 2 模式 |
| 前端保存链路（EditHeader 自动保存 PATCH） | 译文保存接口独立（PUT translations），**不走组件自动保存**（避免 debounce 打架），但复用 update 服务的鉴权与错误处理模式 |
| C 端 `getServerSideProps` 服务端取数 | `?lang=` 在服务端解析，取到 translations 直接替换文案后渲染，前端零 JS 改动 |
| 全局错误提示链路（ajax.ts 拦截器） | Key 无效/超时/校验失败中文提示零成本 |

### 1.3 数据模型设计（本功能核心）

Question schema 新增字段：

```ts
// 各语言文案译文：只存"文案差异"，不存结构。
// fe_id 与主版本组件一一对应；渲染时未命中则回退主版本文案
translations?: {
  [lang: string]: {
    title: string            // 问卷标题译文
    desc: string             // 问卷描述译文
    texts: {
      [fe_id: string]: {
        // 按 props 文案字段原样存译文，仅含该类型有文案值的字段：
        // questionInfo: { title, desc }
        // questionTitle / questionParagraph: { text }
        // questionInput / questionTextarea: { title, placeholder }
        // questionRadio: { title, options: string[]（仅 text，顺序与主版本一致） }
        // questionCheckbox: { title, list: string[] }
      }
    }
  }
}
```

设计要点：

1. **texts 按 fe_id 索引**而非按数组位置——主版本组件增删后，未受影响组件的译文依然命中（数组索引会全部错位）
2. **选项译文存纯 string 数组**（仅 text）：value 由渲染时按主版本选项结构回填 itemN，译文不携带 value（AI 的 value 不可信铁律）
3. **部分命中 + 回退**：主版本新增组件后旧译文无此 fe_id → C 端回退主版本文案（中英混排可接受，提示用户重新翻译覆盖）；删除组件的孤儿译文随下次 AI 翻译覆盖自然清除
4. **语言码约定**：URL 参数与存储 key 用 ISO 短码（`en/ja/ko/fr/es/ru`），下拉框显示中文语言名；后端不限制语言码取值（透传给提示词），前端下拉约束可选值

### 1.4 文案字段的精确边界（正确性红线）

**翻译**（用户可见文案，AI 接口输入输出）：问卷级 `title/desc` + 各组件 props 的 `title/desc/text/placeholder/options[].text/list[].text`

**绝对不变**：`fe_id`、`type`、`isHidden/isLocked`、`isVertical/isCenter/level`、**选项 value**（后端重写 itemN，与主版本对齐）、`answerCount/isPublished` 等问卷级状态

### 1.5 与前两个功能点的差异

| 维度 | 生成问卷 | 单题优化 | 多语言翻译 |
|---|---|---|---|
| 输出结构 | 凭空构造 | 与输入同构（单组件） | 与输入严格同构（整卷） |
| 落库 | create + update | 不落库（redux） | **写入 translations 字段**（AI 接口纯生成，保存由独立接口负责） |
| 结构风险 | 中 | 低 | **最低**（结构原样，只换文案） |
| 耗时 | 10~30s | 3~10s | 10~30s |

### 1.6 调研发现的注意点

1. **选项顺序必须保持**：译文选项顺序与主版本一致，否则 value 回填错位。提示词硬约束"逐条翻译，不增不减，严格保持顺序"
2. **问卷级 title/desc 与 questionInfo 组件译文一致**：原卷生成时二者一致，翻译也要求一致（仅展示层小瑕疵可容忍）
3. **AI 接口输入投影**：传 `{ type, props }`（剥离 fe_id/title/isHidden/isLocked），输出附 fe_id 映射由前端按索引回填——输入越"纯文案+类型"输出越稳
4. **空问卷边界**：componentList 为空时前端按钮禁用
5. **译文与主版本的一致性窗口**：主版本改动后译文不自动过期（一期），C 端按 fe_id 回退兜底；「重新翻译」随时可全量覆盖刷新

## 二、技术选型

| 决策点 | 选型 | 理由 |
|---|---|---|
| AI 接口 | `POST /api/ai/translate-question`（需登录，纯生成不落库）。Body `{ targetLang, question: { title, desc, componentList: [{ type, props }] } }`，返回同构译文 | 延续"AI 模块不碰库"；与生成/优化同一管道 |
| 保存接口 | `PUT /api/question/:id/translations`，Body `{ lang, translation: { title, desc, texts } }`（需登录 + 仅作者，复用 update 的归属校验模式） | 译文独立于 componentList 保存，不混入自动保存链路 |
| 结构校验 | `translateQuestionSchema = z.object({ title, desc, componentList: z.array(componentSchema) })`（复用 componentSchema，去掉生成问卷 min(3)——翻译不设最少组件数门槛） | 结构同构校验零新造成本 |
| 提示词 | 角色（专业问卷翻译）+ COMPONENT_CONTRACT（共用）+ 翻译规则（只译文案、结构字段原样、选项逐条不增减保持顺序、问卷级与 questionInfo 一致、目标语言地道符合问卷语域） | 单一事实来源 |
| C 端渲染 | `getServerSideProps` 解析 `context.query.lang`，命中 translations 时服务端做文案替换（深拷贝 componentList 后按 texts 覆盖文案字段），再传给现有渲染管道 | 零前端 JS 改动；未命中 lang 或无译文 → 渲染主版本（向后完全兼容） |
| 语言切换 UI（C 端） | **[id].tsx 内**form 上方渲染纯文本链接行（`中文 | English | 日本語`，当前语言高亮，其余链到 `?lang=xx`）；**不改 PageWrapper**（通用组件，错误页也在用，塞语言逻辑污染职责） | 分享场景创建者主导语言；无 JS 与 C 端纯 SSR 风格一致 |
| 流式输出 | 不用，一次性 JSON + loading | JSON 必须完整才能解析 |

### 交互流程设计

```
EditHeader [AI 翻译] 按钮（空问卷禁用）
  → aiConfigured === false → Modal.warning 引导（文案同功能点 1/2）
  → aiConfigured === true → 打开 AITranslateModal
      ├─ idle：语言下拉（默认英语；已翻译过的语言标注"已翻译，将覆盖更新"）
      ├─ translating：loading（预计 10~30s）
      ├─ preview：译文摘要（标题/描述/每题题干摘要对照）
      │     ├─ [重新翻译]：换语言或再来一次
      │     └─ [保存译文]：PUT translations → message.success → 关闭
      └─ 失败 → message.error；含"请先配置" → 同步 Redux + 打开 AISettingsModal

C 端（一期最小）：
  GET /question/:id?lang=en
    → 服务端命中 translations.en → 文案替换后渲染译文版
    → 未带 lang / 无该语言译文 → 渲染主版本（现状不变）
```

## 三、技术可行性评估

| 风险点 | 等级 | 应对 |
|---|---|---|
| 译文破坏结构（丢字段/选项错位） | 低 | componentSchema 严格校验 + 失败反馈重试 1 次；输入即结构模板，比凭空生成稳定 |
| 选项顺序漂移 | 低 | 提示词硬约束"保持顺序、不增不减"；译文存纯 text 数组，渲染时按主版本结构回填 value |
| 主版本改动后译文过期 | 中 | C 端按 fe_id 命中渲染、未命中回退主版本文案（可接受的中英混排）；「重新翻译」全量覆盖刷新；一期不做过期标记 UI |
| 整卷 token 量大 | 低 | 10 题纯文案约 1~2k token，远低于主流模型上下文；55s/60s 超时同级 |
| 翻译质量（术语/文化适配） | 中 | 预览确认 + 随时重新翻译覆盖；机器翻译固有边界不在应用层解决 |
| C 端文案替换逻辑复杂度 | 低 | 按 type 分发替换 7 种文案字段，纯函数可实现，边界清晰 |
| 破坏现有功能 | 极低 | Question 加可选字段（Mongoose 无需 migration，旧文档无 translations 照常工作）；C 端无 lang 参数时行为与现状完全一致 |

总体结论：可行性高。核心工作量在**前端 texts 映射构建**（译文→按 fe_id/字段的文案差异结构）与 **C 端服务端文案替换**。

### 开发点 3-1：后端 AI 接口（question-server-nestjs）

1. `generate-question.schema.ts` 导出 `translateQuestionSchema`：`z.object({ title: z.string().min(1), desc: z.string(), componentList: z.array(componentSchema) })`（componentSchema 复用，无 min(3)）。zod strip 特性自动剥离入参 props 中的 value/checked 等结构字段——进提示词的天然是纯文案投影
2. `ai.service.ts` 新增 `TRANSLATE_SYSTEM_PROMPT` 常量（角色"专业问卷翻译" + COMPONENT_CONTRACT + 翻译规则段）与 `translateQuestion(username, targetLang, question)` 方法：
   - 入参过 translateQuestionSchema 校验（失败 400"问卷数据不合法"）；targetLang 非空校验
   - `requireAiConfig` → 动态 client → `chatWithRetry` 校验输出 → 返回 `{ title, desc, componentList: [{ type, props }] }`
   - **不跑 normalizeOptions**（输出只被前端抽取 text，value 不被使用）
   - 提示词规则要点：只译文案字段（title/desc/text/placeholder/选项 text），布局字段（level/isCenter/isVertical）原样；组件数量、顺序、type 一一对应，禁止增删；选项逐条对应翻译不增减、只写 text；顶层 title/desc 与 questionInfo 组件译文一致；译文地道符合问卷语域
   - 方法结构与 optimizeComponent 完全同构
3. `ai.controller.ts` 加 `POST translate-question`（需登录）

**入参**：`{ targetLang: string, question: { title, desc, componentList: [{ type, props }] } }`
**返回**：`{ errno: 0, data: { title, desc, componentList: [{ type, props }] } }`；未配置 400；数据不合法 400；Key 无效 400；两次校验失败 503

### 开发点 3-2：后端存储（question-server-nestjs）

1. `question.schema.ts` 加 `translations` 可选字段：**`@Prop({ type: Schema.Types.Mixed })` + TS 接口类型**（Map 形态无固定 schema 可言，Mixed 文档化足够；内联对象类型会触发 CannotDetermineTypeError——User.aiConfig 的前车之鉴）
2. `question.service.ts` 新增 `updateTranslations(id, author, lang, translation)`：
   - 归属校验：`updateOne({ _id: id, author }, { $set: { ['translations.' + lang]: translation } })`，`matchedCount === 0` → **显式 403"无权操作该问卷"**（不继承 update 的静默 no-op）
   - `lang` 白名单校验（en/ja/ko/fr/es/ru，防脏 key）
3. `question.controller.ts` 加 `PUT :id/translations`
4. `duplicate` 复制问卷时**丢弃 translations**（`...question.toObject()` 后置 undefined）——复制会全量重新生成 fe_id，继承的 texts 全部变孤儿死数据

**入参**：`{ lang, translation: { title, desc, texts } }`
**返回**：`{ errno: 0, data: null }`；非作者 403；lang 非白名单 400

> 现有自动保存 PATCH 走 UPDATABLE_FIELDS 白名单（不含 translations），天然不会覆盖译文，无需改动。

**已翻译语言的获取**：弹窗打开时自请求 `GET /api/question/:id`（公开接口），从响应取 translations 的 keys——已翻译语言在下拉中标注"已翻译，将覆盖更新"。不动 Redux（translations 在编辑器无其他消费者）。

**texts 映射构建——快照语义（关键设计，吸取功能点 2 闭包漂移教训）**：

- 请求**发起函数内部**对 componentList 做快照
- **译文返回时立即按快照索引构建 texts**（不等保存时才构建）：译文组件靠数组索引对应原组件，若用户在 10~30s 生成期间拖拽排序/删除组件，保存时再用"当前"componentList 按索引对应会错位挂到错误的 fe_id
- 响应时构建则锚定快照：生成期间删了组件 → texts 留孤儿条目（C 端回退，无害）；加了组件 → 无译文（回退，无害）

```
texts[快照组件[i].fe_id] = 按该组件 type 从译文[i].props 抽取文案字段：
  questionInfo → { title, desc }
  questionTitle / questionParagraph → { text }
  questionInput / questionTextarea → { title, placeholder }
  questionRadio → { title, options: 译文选项 text 数组 }
  questionCheckbox → { title, list: 译文选项 text 数组 }
```

**预览对照表**：问卷级（标题/描述原文 vs 译文）+ 每题一行（类型 | 原题干 | 译题干，超长截断）；radio/checkbox 不逐条展示选项，只显示"选项数：4 → 4"确认数量未变。

### 开发点 3-4：C 端渲染（askflow-client）

| 文件 | 动作 | 说明 |
|---|---|---|
| `src/pages/question/[id].tsx` | 修改 | ① `getServerSideProps` 解析 `query.lang`：问卷数据含 `translations[lang]` 时服务端替换文案（深拷贝 componentList → 按 type 用 texts[fe_id] 覆盖文案字段、选项按主版本结构只换 text）后返回；② form 上方渲染纯文本语言链接行（主版本 + 各已翻译语言，当前语言高亮，其余链到 `?lang=xx`），仅在存在 translations 时显示 |
| PageWrapper | **不改** | 通用组件（错误页也在用），语言逻辑只属于问卷填写页 |

**文案替换规则**（与 texts 构建互逆，纯函数）：title/desc/text/placeholder 直接覆盖；options/list 按主版本选项结构逐项替换 `text`（value 保持主版本原值，**不重写**——主版本 value 已是 itemN）。

**两道安全兜底**（缺一不可，均整组件回退主版本）：
1. fe_id 未命中 texts → 回退（主版本新增组件场景）
2. 译文选项数组长度与主版本不一致 → 回退（防 AI 增删选项导致 value 错位——zod 只约束数量范围，不保证与原文相等，这是最后防线）

未带 lang / 无该语言译文 / `?lang=xx` 非法 → 整体渲染主版本，行为与现状完全一致。

### 开发点 3-5：联调验收

**AI 接口级测试清单**：

1. 未登录 401；未配置 400；question 非法（缺 title / componentList 非数组 / options 越界）400
2. 假 Key → 400"API Key 无效"
3. PUT translations：非作者 403；lang 非白名单 400；正常写入后 GET 问卷能读到译文

**用户功能测试清单**（真实 Key）：

1. 编辑页 [AI 翻译] → 选英语 → 翻译 → 预览对照 → 保存 → 重新打开弹窗该语言显示"已翻译"
2. 换语言（日语）重复：多语言共存于同一问卷
3. C 端：`?lang=en` 显示全英文；`?lang=ja` 显示日文；不带 lang 显示中文（原状）；`?lang=xx`（未翻译）回退中文
4. **统一统计**：中文版与英文版各提交答卷 → 统计页答案合并计入同一题目（value 聚合验证——本方案的核心目标）
5. 主版本改文案/加组件 → `?lang=en` 中新组件回退中文（混排可接受）；重新翻译覆盖后恢复全英文
6. 错误分支：未配置引导；假 Key 提示；空问卷按钮禁用
7. 回归：编辑/自动保存/AI 生成/AI 优化/发布/统计全链路正常

## 五、验收标准

1. 编辑页 [AI 翻译] 可用：选语言 → 生成 → 预览 → 保存；多语言共存；覆盖更新
2. C 端 `?lang=` 正确渲染对应语言；无 lang/未翻译语言回退主版本
3. **跨语言答卷统一统计**（核心验收）：不同语言版本提交的答卷在同一统计中合并
4. 主版本结构字段（fe_id/type/value/布局/隐藏锁定）在译文中严格不变
5. 译文保存后自动保存/发布/C 端/统计全链路零回归
