## 任务 1：补 `.env.example`

### 1.1 现状

- 后端已有 `.env`（已被 `.gitignore` 忽略），内容为：

```
MONGO_HOST=127.0.0.1
MONGO_PORT=27017
MONGO_DATABASE=nestdb
```

- 变量消费点：[app.module.ts](../../question-server-nestjs/src/app.module.ts#L17-L21) 通过 `ConfigService` 读取 `MONGO_HOST` / `MONGO_PORT` / `MONGO_DATABASE` 拼接 MongoDB 连接串。

### 1.2 发现的附加风险点（需确认是否纳入）

- JWT 密钥**硬编码**在 [constants.ts](../../question-server-nestjs/src/auth/constants.ts#L1-L3)：`secret: 'xxYx&&111'`，未走环境变量。
- 该密钥若随代码提交到 GitHub，任何拿到仓库的人都能伪造登录 token，属真实安全隐患。

### 1.3 计划改动

1. 新建 `question-server-nestjs/.env.example`，列出 `MONGO_HOST` / `MONGO_PORT` / `MONGO_DATABASE` 及说明。
2. （可选）将 JWT 密钥迁移到环境变量：`.env` 与 `.env.example` 增加 `JWT_SECRET`；[constants.ts](../../question-server-nestjs/src/auth/constants.ts) 改为从 `process.env.JWT_SECRET` 读取并保留默认值兜底；[auth.module.ts](../../question-server-nestjs/src/auth/auth.module.ts#L13) 的 `JwtModule.register` 改用 `ConfigService` 注入。

### 1.4 决策点

- **是否顺带把 JWT 密钥迁移到 env？**（推荐做，安全加固；若不做，本任务仅新增 `.env.example` 记录三个 Mongo 变量。）

### 1.5 验收

- 删除本地 `.env` 后，复制 `.env.example` 为 `.env`，`npm run start:dev` 能正常连库启动。

## 任务 2：补数据库索引

### 2.1 现状（无索引，高频查询字段裸奔）

- [answer.schema.ts](../../question-server-nestjs/src/answer/schemas/answer.schema.ts)：`questionId` 只标 `required: true`，无索引。但 `count` / `findAll` 均按 `questionId` 查询，并按 `createdAt` 降序排序（[answer.service.ts](../../question-server-nestjs/src/answer/answer.service.ts#L27-L45)）。
- [question.schema.ts](../../question-server-nestjs/src/question/schemas/question.schema.ts)：`author` / `isDeleted` / `isStar` 均无索引。但列表查询按 `author + isDeleted`（+ 可选 `isStar`）过滤，按 `_id` 降序排序（[question.service.ts](../../question-server-nestjs/src/question/question.service.ts#L126-L165)）。

### 2.2 计划改动

1. `answer.schema.ts` 末尾新增复合索引（覆盖「按问卷查询 + 按时间倒序」这一最高频访问路径）：

```ts
export const AnswerSchema = SchemaFactory.createForClass(Answer)
AnswerSchema.index({ questionId: 1, createdAt: -1 })
```

2. `question.schema.ts` 末尾新增复合索引（覆盖「按作者查列表 + 回收站过滤 + 倒序」）：

```ts
export const QuestionSchema = SchemaFactory.createForClass(Question)
QuestionSchema.index({ author: 1, isDeleted: 1, _id: -1 })
```

### 2.3 决策结论（已确认）

- `isStar` 不单独建索引：仅建上述两个基础复合索引，`star` 列表查询复用 `author + isDeleted` 前缀，先不过度设计。

### 2.4 验收

- 服务启动后 MongoDB 自动创建索引；用 `db.answers.getIndexes()` / `db.questions.getIndexes()` 确认存在。
- 对 `find({ questionId }).sort({ createdAt: -1 })` 执行 `explain()`，确认 `IXSCAN`（走索引）而非 `COLLSCAN`（全表扫描）。

## 任务 3：后端单测 `ai.service.ts`

### 3.1 现状

- 测试框架：Vitest（[vitest.config.ts](../../question-server-nestjs/vitest.config.ts) `include: ['**/*.spec.ts']`，`globals: true`）。
- 现有测试仅 [app.controller.spec.ts](../../question-server-nestjs/src/app.controller.spec.ts)（模板 Hello World）。
- `AiService` 构造依赖 `UserService` / `QuestionService` / `AnswerService` 三个注入（[ai.service.ts](../../question-server-nestjs/src/ai/ai.service.ts#L195-L199)）。

### 3.2 测试目标（按价值从高到低）

**第一梯队：纯逻辑方法（无需 mock 网络，最稳、最有说服力）**

1. `_collectOpenTextAnswers` — 验证空值过滤、相同文本合并计数、限量、单条截断 200 字、`totalCount` 含重复的口径。
2. `parseJson` — 纯 JSON、` ```json ` 包裹、非法输入返回 `null`。
3. `normalizeOptions` — radio `options` / checkbox `list` 重写 `value` 为 `itemN` 的规则。
4. `buildInterviewMessages` — 空 history 走开场白、有 history 走续聊；system 内容包含提纲与规则。

**第二梯队：`chatWithRetry`（mock `createClient`，验证重试逻辑）**

5. 正常输出 → 一次通过。
6. 首次输出非 JSON → 触发重试后成功。
7. zod 校验失败 → 触发重试。
8. 连续两次失败 → 抛 `ServiceUnavailableException`。

**第三梯队：`prepareInterviewStream` 校验链（mock service，验证各分支异常）**

9. `questionId` 空 → `BadRequestException`。
10. 问卷不存在 → `NotFoundException`。
11. 非访谈问卷 → `BadRequestException`。
12. 未发布 → `BadRequestException`。
13. 超轮次（≥20）→ `BadRequestException`。
14. 创建者未配置 AI → `BadRequestException`。
15. 正常 → 返回一个流式闭包函数。

### 3.3 技术方案：如何隔离依赖与 mock

- 用 `Test.createTestingModule` 组装，`providers` 里给 `AiService` 注入三个 `useValue` mock：

```ts
const module = await Test.createTestingModule({
  providers: [
    AiService,
    { provide: UserService, useValue: mockUserService },
    { provide: QuestionService, useValue: mockQuestionService },
    { provide: AnswerService, useValue: mockAnswerService },
  ],
}).compile()
service = module.get(AiService)
```

- 网络隔离：`chatWithRetry` 内部调用私有 `createClient`，用 `vi.spyOn` 替换为假 client，避免真实请求：

```ts
vi.spyOn(service as any, 'createClient').mockReturnValue({
  chat: { completions: { create: vi.fn() } },
})
```

- 私有方法调用：TS 的 `private` 仅编译期约束，运行时可直接 `(service as any)._collectOpenTextAnswers(...)` 访问。

### 3.4 决策点

- 测试文件命名：`src/ai/ai.service.spec.ts`（与 `include: ['**/*.spec.ts']` 匹配）。
- 是否设置覆盖率门槛（如 `coverage.thresholds`）？建议一期先跑通、不留门槛，避免过度设计。

### 3.5 验收

- `npm test`（即 `vitest run`）全绿，无新增失败。
- 覆盖上述 15 个用例中至少第一、第二梯队的全部用例。
