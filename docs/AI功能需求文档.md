# AskFlow AI 功能需求文档

> 目标：将 AskFlow 升级为 AI 全栈网页应用。本文档按问卷生命周期（创建 → 填写 → 分析）梳理 AI 结合点，作为后续开发的实施依据。

## 一、创建端：让 AI 帮用户做问卷（最实用）

### 1. AI 生成问卷（强烈推荐，性价比最高）

用户输入一句话需求（如"我要做一个食堂满意度调查"），AI 直接生成完整问卷：标题、描述、题目、选项。

- 技术方案：用 LLM 的 function calling / structured output，直接输出 `componentList` 的 JSON 结构（type、title、props），前端拿到即可进编辑器
- 现有 schema 就是现成的"提示词约束模板"，每种组件（radio/checkbox/input）的 JSON 形状喂给模型即可

### 2. AI 补全 / 润色单个题目

用户写了"你多久运动一次？"，AI 建议补上"从不/偶尔/每周1-2次/每周3次+"这类选项；或把口语化标题改写得更规范。

- 落地形式：PropComponent 属性面板里的一个"AI 优化"小按钮

### 3. 多语言翻译

一键把问卷翻译成英文/多语言版本，为"分享给外国人填写"铺路。

## 二、填写端：让填写体验智能化（最有差异化）

### 4. 对话式问卷（C端杀手锏）

把传统"一页表单"变成 AI Agent 逐题对话：像聊天一样一个问题一个问题地问，根据前面的回答动态追问。比如用户选了"对食堂不满意"，追问"主要是哪方面？口味/卫生/价格"。

- C端是 Next.js，天然适合聊天式 UI（流式输出）
- 提交时把对话记录映射回 `answerList` 结构，**后端存储和统计逻辑完全不用改**

### 5. 填写助手（答疑）

填写者对题目有疑问时，AI 基于问卷上下文实时解释"这道题该怎么理解"——对复杂量表类问卷很有用。

### 6. 智能防作弊

AI 检测答卷质量：开放式答案是否为乱填/复制粘贴/机器人行为，标记可疑答卷供创建者筛除。

## 三、分析端：让统计更聪明（最出效果）

### 7. AI 总结开放式答案

针对 `questionTextarea/questionInput` 这类文本答案（目前只能人工逐条看），AI 可以：

- 批量聚类：把 200 条自由回答归纳成"主要意见 5 类 + 占比"
- 情感分析：正面/负面/中性分布

### 8. AI 分析报告

统计页加"AI 解读报告"按钮：把 `getStatList` 的统计数据喂给模型，生成一段结论文案 + 改进建议，甚至自动配图表描述。

### 9. 交叉分析问答

创建者直接问 AI："选'不满意'的人里，哪个食堂窗口被吐槽最多？"——AI 现查数据回答（简化的 Text-to-Query）。

## 四、技术落地（结合现有架构）

| 事项 | 方案 |
|---|---|
| 模型接入 | NestJS 新建 `ai/` 模块，统一 OpenAI 兼容接口，可切换 DeepSeek / 通义 / GLM（成本低、国内可用） |
| 流式输出 | SSE（`text/event-stream`），前端 EventSource 接收，逐字打字机效果 |
| 写入侧 | function calling 保证输出符合 `componentList` schema，生成后直接走现有 redux 编辑器流程 |
| 读取侧 | 答卷分析用异步任务思路：提交答卷后标记"待分析"，后台批量跑，统计页展示结果 |
| 鉴权 | AI 接口**不能** `@Public()`（烧钱），必须登录 + 按用户限流（如每天 N 次生成额度） |

## 五、实施优先级

```
第一期：AI 生成问卷（1）+ AI 总结答卷（7）
        → 成本最低、demo 效果最炸、B端C端都能演示
第二期：AI 分析报告（8）+ 题目优化（2）
第三期：对话式问卷（4）→ 产品差异化核心，工作量最大
```

第一期完成后，项目即可对外展示为"**AI 驱动的问卷平台**"——生成和分析两端都有真实 LLM 调用。
