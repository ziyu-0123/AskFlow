# 02 · 整体架构

## 1. 系统上下文（三端协作）

```
┌─────────────────────────┐         ┌──────────────────────────┐
│   askflow（本仓库）B 端   │         │   askflow-client  C 端    │
│   React SPA :5173        │         │   Next.js :3000           │
│  创建/编辑/发布/统计       │         │  问卷填写 / AI 访谈(SSE)   │
└───────────┬─────────────┘         └────────────┬─────────────┘
            │  REST /api/** (JWT Bearer)          │
            ▼                                     ▼
      ┌──────────────────────────────────────────────┐
      │        question-server-nestjs  :3005          │
      │   用户/JWT · 问卷 CRUD · 答卷统计 · LLM 调用   │
      │   （BYOK：用用户存的 Key 转发 OpenAI 兼容接口） │
      └──────────────┬───────────────────────────────┘
                     ▼
              ┌─────────────┐        ┌──────────────┐
              │   MongoDB   │        │ LLM 供应商     │
              │ (Mongoose)  │        │ DeepSeek/GLM… │
              └─────────────┘        └──────────────┘
```

- B 端与 C 端都只跟后端通信，彼此通过**分享链接**衔接：B 端拼 `${VITE_CLIENT_BASE}/question/{id}` 生成链接与二维码。
- AI 请求全部由后端代理转发（用户 BYOK Key 存在服务端），前端无任何直连 LLM 的逻辑。

## 2. 前端分层架构

```
main.tsx
  └─ <Provider store>            ← Redux 全局唯一 store
       └─ <App> → <RouterProvider router>
            │
            ├─ MainLayout（根 shell，eager）
            │    ├─ useLoadUserData / useNavPage   ← 鉴权守卫（hooks 实现，非路由守卫）
            │    ├─ Home / Login / Register
            │    └─ ManageLayout → List / Star / Trash
            │
            └─ QuestionLayout（懒加载，独立于 MainLayout）
                 ├─ /question/edit/:id       → Edit（拖拽编辑器）
                 ├─ /question/stat/:id       → Stat（统计）
                 └─ /question/interview/:id  → InterviewEdit（访谈配置）

分层：pages/layouts（页面编排）
      │  依赖
      ├─ components/QuestionComponents  组件协议 + 7 种问卷组件
      ├─ components/DragSortable        dnd-kit 封装
      ├─ hooks/                          数据加载 / store 读取 / 快捷键
      ├─ store/                          Redux Slice（components 带 undo）
      └─ services/                       axios 封装 + 后端接口
```

## 3. 核心数据流

### 3.1 列表 / 用户信息（读为主）

```
URL searchParams（keyword/page/pageSize）
   → hooks/useLoadQuestionListData（ahooks useRequest, refreshDeps=location.search）
   → services/question.getQuestionListService
   → 后端 GET /api/question
   → 拦截器解包 data → normalizeQuestion（_id→id, 日期格式化）
   → 组件本地 state 渲染（列表数据不进 Redux）
```

### 3.2 编辑器（Redux 为核心）

```
进入 /question/edit/:id
  → useLoadQuestionData：GET /api/question/:id
  → dispatch(resetComponents(componentList)) + dispatch(resetPageInfo(...))
  → EditCanvas / Layers / ComponentProp 均从 useGetComponentInfo 读 store 渲染
  → 用户编辑（点选/拖拽/改属性/增删组件）→ dispatch 各 action
  → SaveButton 监听 [componentList, pageInfo] 变化 → 防抖 1s 自动 PATCH 保存
  → ctrl.z / ctrl.shift.z → redux-undo 的 undo/redo（历史栈上限 20）
```

### 3.3 AI 能力（统一模式）

所有 AI 弹窗遵循同一套交互状态机与错误兜底：

```
未配置（Redux user.aiConfigured=false）→ 点击按钮 → Modal.warning 引导去「AI 设置」
已配置 → 60s 长请求（Spin + "约需 10~30 秒"）→ 成功：预览/结果态
                                        └→ 失败：
                                             - 拦截器统一 message.error
                                             - 若 err 含"请先配置"（后端 400）：
                                               dispatch(updateAiConfiguredReducer(false))
                                               直接打开 AISettingsModal（标记过期兜底）
```

## 4. 模块依赖关系图

```
router ────────────► layouts ──────────► pages
   │                    │                  │
   │                    ▼                  ▼
   │                 hooks ◄────────  components（公共 + 问卷组件）
   │                    │                  │
   │                    ▼                  ▼
   └───────────────► store ◄─────────── pages/components
                        │
                        ▼
                    services ──► utils/user-token（token 读写）
                        │
                        ▼
                     ajax.ts（axios 实例 + 拦截器）
```

要点：

- `services` 是**唯一**发起网络请求的层；`store` 不做请求，只持有纯状态。
- `components/QuestionComponents` 是协议层：`store` 的类型（`ComponentPropsType`）反向依赖它，`pages` 通过 `getComponentConfByType` 动态渲染。
- `hooks` 是 `pages/layouts` 与 `store/services` 之间的胶水层。
- `constant` 被列表、统计、图表多处引用（分页大小、URL 参数 key、统计配色）。

## 5. 鉴权设计

没有使用路由 loader/guard 组件，而是**在每个顶层 Layout（MainLayout、QuestionLayout）里调用同一对 hooks**：

| Hook | 职责 |
| --- | --- |
| `useLoadUserData` | Redux 无 username 时调用 `GET /api/user/info` 探活：成功 → `loginReducer`；失败（未登录）→ 静默（拦截器对"未登录/Token 无效"不弹 toast） |
| `useNavPage(waitingUserData)` | 等待探活结束后重定向：已登录访问 /login /register → `/manage/list`；未登录访问需登录页 → `/login`；`/`、`/login`、`/register` 免登录 |

token 生命周期：登录成功 `setToken`（localStorage）→ axios 请求拦截器统一附加 `Authorization: Bearer <token>` → 退出登录 `removeToken` + `logoutReducer`。
