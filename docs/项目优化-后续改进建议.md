## 一、高优先级：安全隐患（面试最加分）

### 1. 密码明文存储（最该改）

- **现状**：[user.schema.ts](../../question-server-nestjs/src/user/schemas/user.schema.ts) 的 `password` 为 `@Prop({ required: true })`，[user.service.ts](../../question-server-nestjs/src/user/user.service.ts) 注册与登录均明文比对。
- **风险**：数据库泄露即密码泄露，属安全硬伤。
- **方案**：引入 `bcrypt`，`create` 时加盐哈希、`signIn` 时 `compare` 校验；`AuthService.signIn` 的 `findOne({ username, password })` 改为先按 username 查、再 compare。
- **简历收益**：体现「密码加盐哈希」安全意识。

### 2. CORS 全开

- **现状**：[main.ts](../../question-server-nestjs/src/main.ts#L10) 的 `app.enableCors()` 允许任意来源。
- **风险**：任意站点可调用接口。
- **方案**：`enableCors({ origin: 白名单 })`，生产用环境变量配置。
- **简历收益**：体现「接口来源管控」。

### 3. JWT 密钥依赖默认值兜底

- **现状**：`JWT_SECRET || 'xxYx&&111'`，忘配环境变量时静默用弱密钥。
- **方案**：生产环境（`NODE_ENV === 'production'`）缺少 `JWT_SECRET` 时启动即报错。
- **简历收益**：体现「配置强校验」。

### 4. AI 接口无通用限流

- **现状**：仅业务级「轮次上限 20」，接口级无限流。
- **方案**：引入 `@nestjs/throttler`，对 `/api/ai/*` 做每用户每日/每分钟限额，成本兜底。
- **简历收益**：体现「成本与滥用防护」。
