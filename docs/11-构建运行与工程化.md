# 11 · 构建运行与工程化

## 1. 快速启动

```bash
# 1) 后端 + MongoDB（question-server-nestjs 仓库）
cd question-server-nestjs
npm install
cp .env.example .env      # 配置 MONGO_URI / JWT_SECRET / CORS_ORIGINS
npm run start:dev          # http://localhost:3005
# 或 docker compose up 一键启动

# 2) 本管理端
npm install
npm run dev                # http://localhost:5173

# 3) C 端填写端（askflow-client 仓库）
cd askflow-client
npm install && npm run dev # http://localhost:3000
```

完整体验流程：注册 → 顶栏「昵称 → AI 设置」填入自己的 API Key（BYOK）→ 创建/编辑问卷 → 发布 → 用 C 端链接答卷 → 回统计页看图表与 AI 报告。

## 2. npm 脚本（[package.json](../../package.json)）

| 脚本                          | 作用                                  |
| --------------------------- | ----------------------------------- |
| `npm run dev`               | Vite dev server（带 `/api` 代理到 :3005） |
| `npm run build`             | `tsc -b && vite build`（先做类型检查再构建）   |
| `npm run test` / `test:run` | Vitest（watch / 单次执行）                |
| `npm run lint`              | ESLint 检查 `src/**`                  |
| `npm run format`            | Prettier 全量格式化                      |
| `npm run preview`           | 预览构建产物                              |
| `npm run analyze`           | vite-bundle-visualizer 包体积分析        |
| `npm run prepare`           | Husky 安装（postinstall 自动执行）          |

## 3. Vite 配置要点（[vite.config.ts](../../vite.config.ts)）

### dev 代理

```ts
server: { proxy: { '/api': { target: 'http://localhost:3005', changeOrigin: true } } }
```

### 生产分包（manualChunks，函数形式——Rolldown 只支持函数式）

| chunk             | 内容                                                                          | 目的                         |
| ----------------- | --------------------------------------------------------------------------- | -------------------------- |
| `react-vendor`    | react / react-dom / scheduler / react-is / react-router(-dom) / react-redux | 每页必用，长期缓存                  |
| `recharts-vendor` | recharts                                                                    | 仅统计页用，按需加载                 |
| `redux-vendor`    | @reduxjs / immer / redux-undo                                               | Redux 生态                   |
| `dnd-vendor`      | @dnd-kit/\*                                                                 | 仅编辑页用                      |
| （antd 不强制拆分）      | —                                                                           | 让 Rolldown 按组件自动拆分（按需加载更优） |

### 测试配置（同文件 `test` 字段）

* `environment: 'jsdom'`、`globals: true`、`setupFiles: './src/setupTests.ts'`

* `pool: 'threads'`（Windows 下 forks 池 worker 启动易超时的规避）

## 4. TypeScript 工程

* `tsconfig.json` 聚合 `tsconfig.app.json`（src 应用代码）与 `tsconfig.node.json`（vite.config 等 node 侧代码）；

* 注意 `erasableSyntaxOnly` 约束：**不允许 enum 等不可擦除语法**，代码中用 `as const` 对象替代（例：RightPanel 的 `TAB_KEYS`）。

## 5. 测试

* 运行器 Vitest 4 + @testing-library/react + jest-dom；

* 用例分布在各问卷组件的 `Component.test.tsx`（渲染 + 交互断言，见各组件目录）；

* 执行：`npm run test:run`。

## 7. 环境变量汇总

| 变量                 | 作用域 | 默认                       | 说明                  |
| ------------------ | --- | ------------------------ | ------------------- |
| `VITE_API_BASE`    | 本项目 | `http://localhost:3005/` | 后端地址（axios baseURL） |
| `VITE_CLIENT_BASE` | 本项目 | `http://localhost:3000`  | C 端地址（分享链接/二维码拼接）   |

后端与 C 端各自的环境变量见各自仓库 README（`MONGO_URI`、`JWT_SECRET`、`CORS_ORIGINS`、`NEXT_PUBLIC_API_BASE` 等）。

## 8. 部署

* 托管：**Netlify**（[public/\_redirects](../../public/_redirects) 提供 SPA fallback：`/* → /index.html 200`，刷新非根路由不 404）；

* 在线 demo：管理端与 C 端均部署在 netlify.app，后端部署在 Railway（Swagger 文档 `/api/docs`）；

* 部署时需在托管平台配置两个 `VITE_*` 环境变量指向真实后端 / C 端域名。
